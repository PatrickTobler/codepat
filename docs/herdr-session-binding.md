# Herdr native session binding

CodePat's internal `agent_session_id` is normalized from the installed Herdr 0.9 API's **output** field `agent_session: {source, agent, kind, value}`. The flat `agent_session_id` is a hook-report **input** field; reading only it from agent-list output discards real native session evidence. Protocol 22's bundled `herdr api schema --json` defines `AgentSessionInfo` with those four required fields. CodePat accepts supported provider IDs only when provider, `herdr:PROVIDER` source and `kind: id` match. Wrong source/provider, path references, invalid IDs and contradictory flat/nested values remain unbound. A legacy flat adapter field remains compatible; malformed native metadata cannot fall back to it.

Archived reuse still requires exact owner/task/name/cwd/pane/generation and saved-session binding, with explicit continuity evidence for legacy records. This adapter change does not make a missing native reference appear, authorize a command, reconcile a hold or permit an uncertain effect replay.

## Retained Codex limitation

Read-only live acceptance found an owned Codex process started with `resume --last`, no explicit provider ID in its startup arguments, and no native session reference in Herdr's agent output. `herdr integration status` reports the Codex integration **not installed**. Idle/interactive-ready describes input readiness, not conversation identity.

Herdr's supported Codex integration reports identity from an authentic Codex `SessionStart` hook using `pane.report_agent_session`. The hook requires an actual session ID and transcript-path payload, rejects mismatched inherited thread IDs, and does not provide a retroactive attach/inspection command for an already-running process. Herdr also retains explicit `agent start ... resume SESSION_ID` identity; `--last` is not that evidence. Installing a hook now does not prove that an old process emitted or loaded it. Do not manually synthesize a SessionStart payload, report a guessed ID, restart the retained agent, or install/update Herdr to manufacture acceptance.

The narrowly authorized process inspection found an open rollout file on that owned foreground Codex PID. Only its first `session_meta` record was read; it matched the owned worktree and process start time stayed stable. This is private diagnostic evidence, not currently a supported Herdr session binding, proof of the original requested conversation, or authorization to bypass the missing-metadata guard. No unrelated transcripts were inspected. No production fallback scans Codex history, newest files or process environments.

### Minimal missing capability

For future authorized launches, configure the supported Codex SessionStart integration and verify authentic native metadata before needing recovery. This does not unblock the retained process retrospectively.

For the already-running process, the missing supported capability is a **read-only native session inspection/export** from Herdr or Codex that binds the currently owned foreground Codex process to its active thread ID, including pane/terminal identity and process start or agent revision fencing. It must refuse missing/ambiguous/replaced processes or multiple possible session references. On Linux an upstream implementation could validate a single owned open rollout descriptor and its session metadata against the provider process, rereading process identity before returning; this is a proposed upstream capability, not an existing command or a CodePat heuristic. An authoritative provider-side current-thread query would also suffice. Upstream acceptance must cover resumed sessions, stale/inherited metadata, multiple descriptors, process replacement, nested agents and no session switching or writes. The coordinator must independently verify original saved-conversation continuity and use the existing owner recovery-evidence boundary. No upstream issue or change was submitted by this investigation.
